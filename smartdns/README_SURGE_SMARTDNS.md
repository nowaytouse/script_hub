# Surge + SmartDNS 高性能架构全纪录 (V44.7 True Dual-Stack)

本方案彻底替代了原先不稳定的 MosDNS 递归重定向架构，通过内核级流量接管和逻辑重构，实现国内域名的极致秒开与国际域名的安全代理防泄漏。

## 核心架构设计

1. **内核级物理重定向 (PF Redirection)**
    - 突破 macOS 权限：采用非 root 用户运行 SmartDNS 监听 \`6053\` 端口。
    - UDP/TCP 全协议覆盖：利用 pfctl 将 \`lo0(127.0.0.1)\` 的 53 端口 UDP 及 TCP 流量强行 \`rdr\` 至 \`6053\`。这**彻底解决**了复杂 CNAME 域名（例如 \`baidu.com\` 的衍生子域名）下大报文触发 TCP 回源时的 \`Empty DNS answer\` 死锁。

2. **精细与严格的防泄漏分流 (Exact DNS Steering)**
    - **国内直连 (Group \`cn\`)**：依托 \`cn.txt\` 共计 12 万+条规则列表及手工指定的 \`baidu.com\` 等巨头大厂根域名。国内解析直接使用高速双栈上游（DoH + UDP 垫底）。
    - **默认代理容灾 (Group \`proxy\`)**：采用 MosDNS 类似的“剩余一律走海外代理”机制。未在国内名单的域名（即 \`/./\` 匹配）强制使用境外的 DoH 上游。此策略彻底根治了并发查询带来的 DNS 污染泄漏以及伪造 IP 被 Surge 错误认定为直连的风险。

3. **全链路容错的双栈注入 (True Dual-Stack Fallback)**
    - 在 Bootstrap 引导阶段及国内 \`cn\` 查询池内，均注入了阿里 (\`2400:3200::1\`) 与 腾讯 (\`2402:4e00::\`) 的原生 IPv6 UDP 连线。
    - 配合 \`dual-stack-ip-selection\`，在保持纯净解析的同时支持极致的 V4/V6 过渡。

4. **协议隔离与净化**
    - 使用 \`force-qtype-soa 65\` 强制所有 Type 65 (HTTPS) 查询返回 SOA 空响应，剔除了非标空净报文，避免 Surge 在 RULE-SET LAN 等匹配中误判空答案。
    - 关闭不必要的 \`speed-check-mode\`，直接返回最短第一跳响应以挑战理论的极低延时。

## 运维与使用手册
以下为管理、重启、诊断这套架构时的常用操作。

### 1. 补齐内核防火墙 (必须)
若重启或失效，需执行此操作恢复 UDP 与 TCP 的物理流量接管：
```bash
echo "rdr pass on lo0 inet proto udp from any to 127.0.0.1 port 53 -> 127.0.0.1 port 6053
rdr pass on lo0 inet proto tcp from any to 127.0.0.1 port 53 -> 127.0.0.1 port 6053" | sudo pfctl -a com.apple/smartdns -f -
```

验证 PF 规则是否生效 (正确应回显 udp/tcp 两条规则)：
```bash
sudo pfctl -a com.apple/smartdns -s nat
```

### 2. 重启与生效生效配置
修改配置后应当重启 SmartDNS 服务使其应用配置，并清空 Surge 本地建立的负缓存：
```bash
pkill smartdns
/opt/homebrew/sbin/smartdns -c /tmp/smartdns.conf &
```
> **注意**：重启进程后务必在 Surge 菜单栏选择 **[工具] > [清除 DNS 缓存]**，防止由于负缓存造成的历史 Empty 问题复现。

### 3. 日志审计与诊断
SmartDNS 已配置输出访问审计日志，如需诊断特定域名的走向组别：
```bash
tail -f /tmp/smartdns_audit.log | grep "要排查的域名"
```

### 4. 国内直连白名单维护
如果遇到需临时放行或指定直连解析的国内特殊域名：
- 修改 \`ruleset/custom_direct.list\` 文件添加对应行。
- 执行 \`python scripts/merge_shadowrocket_rules.py\` 重新编译规则并会重新生成给 SmartDNS 所用的域名表。
